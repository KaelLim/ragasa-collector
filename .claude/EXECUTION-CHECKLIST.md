# CLAUDE 開發原則執行檢查清單 v1.0

## 🚨 **強制執行檢查點系統**

### **階段一：開發前強制檢查 (Pre-Development Checkpoint)**

#### **📋 無文件，不實作檢查**
- [ ] **官方文檔確認**：是否已找到並閱讀相關的官方技術文檔？
- [ ] **API 規範驗證**：是否確認了 API 端點、認證方式、請求/回應格式？
- [ ] **版本兼容性**：是否確認了工具/服務的確切版本要求？
- [ ] **速率限制了解**：是否了解 API 的速率限制和錯誤處理？
- [ ] **禁止維基百科**：是否避免引用維基百科作為技術資料來源？

**🛑 如果任何項目未完成，禁止開始實作**

#### **📋 需求與架構檢查**
- [ ] **根本問題定義**：能否用一句話解釋要解決的核心問題？
- [ ] **實際需求確認**：是否基於明確的使用者需求而非技術興趣？
- [ ] **最簡方案評估**：是否考慮了最簡單的解決方案？
- [ ] **架構必要性**：是否避免了不必要的架構複雜性？

### **階段二：開發過程中檢查 (每 30 分鐘強制執行)**

#### **📋 原則遵循檢查**
- [ ] **目標一致性**：當前實作是否仍然對應原始問題？
- [ ] **文檔依據**：當前實作是否基於已驗證的官方文檔？
- [ ] **複雜度警報**：是否出現超過 3 層抽象的設計？
- [ ] **假設警報**：是否開始基於「我認為應該」而非「文檔要求」實作？

**🛑 如果出現警報，立即停止並執行暫停重評程序**

#### **📋 實際測試檢查**
- [ ] **功能可驗證**：當前階段是否有可測試的功能？
- [ ] **端到端路徑**：是否從使用者角度驗證功能可用性？
- [ ] **錯誤場景**：是否測試了錯誤和邊界情況？

### **階段三：完成前強制檢查 (Pre-Completion Checkpoint)**

#### **📋 實際測試優於文件檢查**
- [ ] **端到端測試**：是否完成了完整的使用者流程測試？
- [ ] **實際可用性**：功能是否在實際環境中正常運作？
- [ ] **自我使用測試**：開發者本人是否能順利使用該功能？
- [ ] **邏輯一致性**：聲稱的功能與實際測試結果是否一致？

**🛑 如果測試未通過，禁止宣稱功能完成**

#### **📋 架構思維檢查**
- [ ] **生產環境適用**：解決方案是否適合實際部署環境？
- [ ] **需求完全符合**：是否完全滿足實際業務需求？
- [ ] **避免捷徑思維**：是否避免了因複雜而選擇不符需求的簡單方案？
- [ ] **擴展性考慮**：架構是否保持了合理的擴展性？

## 🔧 **容器環境特殊檢查**

### **📋 Docker 代碼同步驗證**
- [ ] **容器重建確認**：修改代碼後是否重建了容器映像？
- [ ] **代碼同步驗證**：是否確認修改確實存在於運行中的容器？
- [ ] **時間戳檢查**：容器啟動時間是否在代碼修改之後？
- [ ] **映像快取清理**：是否排除了映像快取造成的舊版本問題？

### **📋 端口管理檢查**
- [ ] **端口狀態檢查**：啟動服務前是否檢查端口佔用？
- [ ] **智能複用判斷**：如發現開發服務器運行，是否選擇複用而非重啟？
- [ ] **人類服務器保護**：是否確認沒有終止人類手動啟動的服務器？
- [ ] **端口衝突解決**：是否妥善處理了端口衝突情況？

## ⚠️ **原則違反立即停止信號**

### **🚨 無文件實作警報**
**立即停止條件**：
- 開始基於名稱相似性或經驗猜測 API 行為
- 未找到官方文檔就開始實作整合
- 引用維基百科或非官方資料作為技術依據

### **🚨 測試跳過警報**
**立即停止條件**：
- 宣稱功能完成但自己無法使用
- 測試失敗但仍繼續開發
- 超過 2 小時沒有可運行的驗證

### **🚨 架構偏離警報**
**立即停止條件**：
- 為了技術簡單而忽視實際部署需求
- 明知需求是 A 但提供 B 方案
- 遇到技術難題就改變問題定義

### **🚨 複雜度失控警報**
**立即停止條件**：
- 無法用一句話解釋為什麼需要此功能
- 建立超過 3 層的抽象設計
- 因為「有趣」而非「必要」增加功能

## 📝 **檢查清單使用說明**

### **強制執行機制**
1. **每個開發會話開始**：必須完成「開發前檢查」
2. **每 30 分鐘**：執行「過程中檢查」
3. **宣稱完成前**：必須通過「完成前檢查」
4. **遇到警報信號**：立即停止並執行暫停重評程序

### **檢查清單更新**
- 每次違反原則後，必須更新相應檢查項目
- 每月回顧並優化檢查清單內容
- 根據專案特性調整專用檢查項目
